# Reminder settings

This local Expo module exposes two Android APIs that `expo-notifications` does not expose:

- `AlarmManager.canScheduleExactAlarms()` checks real special-access permission.
- `Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM` opens the permission screen for this app.

Expo autolinks the module from `modules/`; the root Android project stays generated by EAS.
Changing this Kotlin code requires a new development or production build. A Metro reload alone is not enough.
The TypeScript wrapper skips the Android permission on iOS and Android versions before 12.
An older development build reports the missing module without crashing the task list.

Phone checks after rebuilding:

1. Turn off Alarms & reminders, enable a task reminder, and follow the setup.
2. Return without granting access: Continue must stay disabled.
3. Grant access and return: both steps should show Ready, and Continue should work.
4. Save a reminder a few minutes ahead, lock the phone, and confirm delivery.
5. Check notification denial, a disabled Task reminders category, editing and deleting a reminder.

Revoking special access can cause Android to restart the app. The app checks again and reconciles saved future reminders when reopened.
